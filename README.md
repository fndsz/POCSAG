# POCSAG 寻呼发射器 · ESP8266 网页控制端

在原项目 [`359303267/STM32_POCSAG_Transmit`](https://github.com/359303267/STM32_POCSAG_Transmit)
的 `ESP8266源码/ESP8266` 基础上重做，**STM32 端固件不用改，串口命令完全兼容**。

## 一、这次改了什么

| 项目 | 原版 | 本版 |
|---|---|---|
| 手机浏览 | 固定 900px 桌面表格，手机上要来回缩放 | viewport + 响应式栅格：手机每行 2 格卡片，≥660px 自动变 7 列表格 |
| 深色模式 | 无 | 跟随系统，也可右上角 ◐ 手动切，选择记在本地 |
| 群呼 | 20 个复选框，全部共用第 1 组参数 | **10 行表格**：每行独立 频率/地址码/速率/相位，行首勾选「发送」 |
| 天气推送 | 无 | 每行独立「天气」勾选列；每天定时或手动推送；**可带城市名称**；数字机自动改发纯数字 |
| 配置保存 | 不保存，刷新即丢 | 全部写入 LittleFS，掉电不丢，开机自动回填网页 |
| 发送机制 | `delay()` 硬等，发 10 路时网页卡死 | 后台队列非阻塞，发完前网页照样能开，还能「清空队列」 |
| 发射效率 | 固定间隔干等 + 每行都切频 | 自适应间隔 + 同频归组，**10 路群呼从 81 秒降到 21 秒** |
| 页面加载 | 22KB 明文传输 | gzip 预压缩，传输量省 68%，首屏明显变快 |
| Flash | 1MB 空间捉襟见肘 | 默认按 **8MB（FS:6MB OTA:~1019KB）** 打包，4MB 也能用，附一键合并脚本 |
| 固件升级 | 失败只报「网络错误」，看不出原因 | 上传前先体检固件文件；失败给出具体原因；断连不误判为失败 |

### 速度优化具体做了什么

**1. 自适应发送间隔（最大头）**

原版不管消息长短，每条都干等 8 秒。实际上 POCSAG 的发射时长是可以精确算出来的：

```
总比特 = 前导码 576 + 批次数 × 544 + 帧对齐余量 64
批次数 = ceil((1 地址码字 + N 消息码字 + 1 结束码字) / 16)     每批 16 个码字
汉字机：N = ceil(字节数 / 2)     数字机：N = ceil(字节数 / 5)
耗时   = 总比特 / 速率
```

固件按这个公式逐条算等待时间（安全系数 1.4 + 600ms 的 STM32 编码开销，下限 800ms），
短消息不再空等。仿真实测（10 行 / 1200bps / 汉字机）：

| 场景 | 原版 | 本版 | 提速 |
|---|---|---|---|
| 10 行 × 12 字节短消息 | 81.4 秒 | 21.2 秒 | **3.8 倍** |
| 10 行 × 90 字节长消息 | 81.4 秒 | 59.3 秒 | 1.4 倍 |

长消息提速少是必然的 —— 因为它本来就得发射那么久。自适应只在真的空闲时才省。

**2. 同频归组**

切频一次要等 400ms 锁相。原来每行都切，现在把相同频率的行排在一起发（稳定排序，
同频内仍按序号升序）。10 行交替两个频点的极端场景：切频 10 次 → 2 次。

**3. 页面 gzip 预压缩**

ESP8266 的 HTTP 吞吐只有几十 KB/s，30KB 的群呼页要传将近一秒。现在页面预先压成
gzip 存进 Flash，配上 `Content-Encoding: gzip` 由浏览器解压，传输量省 68%：

```
群呼页  30550 → 8059 字节     全部页面 51102 → 16590 字节
```

Flash 占用反而更小了，代价只是几十 KB 的源码体积。想看明文调试可加 `--no-gzip`。

**4. 其他**

- HTTP 分片从 900 字节提到 1460（以太网 MSS），减少 TCP 发送次数
- 状态轮询 700ms → 500ms，队列空立即停，不空转
- 发送按钮防连点（2.5 秒内禁用），避免重复入队

### 固件升级报「网络错误」是怎么回事

这个提示具有误导性，它只说明**浏览器的请求没拿到响应**，既可能是真失败，
也可能是**已经成功了但设备在回话之前就重启了**。原版代码里有两个具体成因：

**① 不校验大小就往 Flash 里写（会崩）**

`Update.begin()` 传的参数是可写上限，但原版从不检查上传的文件是否超限。
一旦传进来的东西比 OTA 分区大 —— 最典型的就是把打包脚本合成的
**整片 Flash 镜像**当固件传 —— 写越界直接导致设备崩溃复位，
TCP 连接随之中断，浏览器只能看到一句「网络错误」，真正原因完全看不到。

现在的处理：**开写之前先用 `Content-Length` 卡一道**，超限直接拒绝并说明：

```
固件太大：收到 4096 KB，可用空间只有 1012 KB。
OTA 只能传 Arduino「导出已编译的二进制文件」得到的程序 bin，
不能传打包脚本合成的整片 Flash 镜像（那个必须用串口烧录）
```

网页端在选完文件后也会先体检：读固件头解析出它是按哪种 Flash 布局编译的
（4MB？1MB？DIO 还是 QIO？），与设备实际容量不符就拦下；
体积接近整片 Flash 的直接判定为「疑似整片镜像」并禁止提交。

**② 响应还没发出去就重启**

原版在响应函数里 `delay(100)` 然后 `ESP.restart()`。100ms 往往不够 lwIP 把
响应真正推到空中，设备先断电了 —— 于是固件其实刷好了，页面却显示失败。

现在的处理：**响应先发，重启挂到 `loop()` 里延后 2 秒执行**，
这 2 秒里继续跑 `server.handleClient()`，让 TCP 把数据发完。

另外，网页端在上传结束（**包括报网络错误**）后不再直接判失败，
而是轮询设备：如果能连上、且编译时间变了 → 升级成功（会提示新固件的编译时间）；
如果连得上但编译时间没变 → 没刷进去；如果一直连不上 → 需要串口重烧。

**③ 顺带修的：OTA 前必须卸载文件系统**

LittleFS 挂载期间做 OTA，两者会争抢 Flash 操作。现在开写前先 `MYFS.end()`；
若升级没能开始（比如容量不够），会把文件系统重新挂回去，保证配置读写不受影响。

### 一句话记住

- **OTA 传**：Arduino「导出已编译的二进制文件」得到的程序 bin，约 400~700 KB
- **串口烧**：`pack_flash.py` 合成的整片镜像，地址 `0x0`

### 关于 core 2.7.4 的兼容性

本版在 **esp8266 core 2.7.4** 上编译通过（也在 3.x 上通过）。

OTA 部分刻意没有使用 `Update.abort()` —— 那是 core 3.x 才有的方法，
在 2.7.4 上会直接报 `'class UpdaterClass' has no member named 'abort'`。
取而代之的做法是把 `Update.begin()` 推迟到真正收到第一个数据包时才调用：
空文件或中途取消时压根不会进入 Updater 状态，也就不需要清理。
这样一套代码两个版本都能编译，不必写 `#if` 分支。

### Flash 模式：自动跟随编译设置

`pack_flash.py` 会读取 `.bin` 的前 4 个字节，里面记着编译时的 Flash 模式/频率/容量，
再用同一组参数去合并。

这解决了一个很隐蔽的问题：esptool 的 `merge_bin` 会按 `--flash_mode`
**改写固件头**。如果 sketch 是按 DOUT 编译的（Arduino 里「Generic ESP8266 Module」
的 Flash Mode 默认就是 DOUT 兼容模式），而打包脚本硬编码成 DIO，
合并出来的镜像头部就变成了 DIO —— **能烧进去但起不来**，而且极难排查。

现在打包时会打印它读到了什么：

```
Flash 参数: DOUT(兼容) / 40M / 4MB  （从 .bin 头部读出）
```

若 `.bin` 是按 1MB 而非 4MB 编译的，会直接告警让你去改 Flash Size。
需要强制覆盖时用 `--flash-mode` / `--flash-freq` / `--flash-size`。

`build_flash.py` 默认用 `dout`（与 Arduino IDE 默认项一致，兼容性最好），
可用 `--flash-mode dio` 切换。

### 每日推送时间：三组

从原来的 1 个时间点扩展为 **3 个**，每组可独立开关：

| 组 | 默认时间 | 默认状态 |
|---|---|---|
| ① | 07:30 | **启用** |
| ② | 12:00 | 关闭 |
| ③ | 18:00 | 关闭 |

默认只开第一组 —— 免得你还没设置就一天推三次。想要更多，勾上即可。

**这里有个不改就白搭的坑**：原来判断「今天推过了没」只用一个 `lastWxDay` 日期。
三组时间共用它的话，第一组一推完就把当天锁死，后两组**永远不触发**，
跟只配一个时间点没区别。

所以改成按时间点分别记录（`wxDoneMask`，每个 bit 对应一组）：
跨天自动清零，各组互不干扰；同一分钟只推一次，避免多条消息挤在串口上。

**兼容性**：老配置文件里只有 `whh`/`wmm` 一个时间的，读进来会自动落到第 1 组并置为启用，
升级后仍按原时间推送，不用重新配。

页面上未勾选的时间点输入框会置灰；如果填了重复时间，会提示「同一分钟只会推送一次」。

 firmware 侧参数：`wt0/wt1/wt2`（HH:MM）+ `won0/won1/won2`（是否启用）。

### Wifi「掉电丢账号密码 / 上电不自动重连」是怎么回事

**根因通常在 Arduino 的「Flash Size」选项上。**

LittleFS 的分区**完全由编译时选的 Flash Size 决定**。而 `esp8266:esp8266:generic`
不带任何选项时，2.7.4 的默认项是 **`1MB (FS:64KB)`** —— 文件系统只在那 64KB 里，
位置在 `0xEB000`，跟 8MB 芯片根本对不上。更糟的是 boards.txt 里还有
`4MB(FS:none)`、`1MB(FS:none)` 这类**完全没有文件系统分区**的布局
（它们的链接脚本把 `_FS_start` 和 `_FS_end` 设成同一个地址，分区大小为 0）。

结果就是：LittleFS 挂不上 → `cfgSave()` 一个字节都写不进去 → 掉电必丢。

**三道防线，已全部加上：**

① **EEPROM 兜底通道**（关键）

EEPROM 的扇区由链接脚本的 `_EEPROM_start` 决定，**并且在所有布局里都有定义**，
包括那几个 `FS:none` 的布局，地址永远跟编译时一致、不依赖文件系统。

所以 Wifi 账号密码现在**双写**：LittleFS 一份 + EEPROM 一份。
读取时文件系统优先，读不到就回退到 EEPROM。这样不管 Flash Size 怎么选，
至少路由器账号密码掉电不丢、上电能自动重连。

② `fsBegin()` 挂载失败自动格式化一次；`cfgSave()` 返回真实结果，
写不进去就通过串口报 `#WIFI+SAVEFAIL`、网页回 `-2` 并红字提示。

③ 打包脚本不再把 1MB/2MB/512KB 的固件默默映射到某个布局
（那样会把地址和容量全搞错），而是直接报错，逼你把 Flash Size 改对再编译。

**自查方法**：Wifi 页新增「存储状态」一行 ——
- 正常 → 「配置存储正常」
- 文件系统不可用 → **红字警告**，并告诉你该选哪个 Flash Size
- 从 EEPROM 恢复 → 提示重新保存一次让两边一致

**根治办法**：Arduino 里把 `Flash Size` 改成
`8MB (FS:6MB OTA:~1019KB)`（8MB 模块）或 `4MB (FS:2MB OTA:~1019KB)`（4MB 模块），
重新编译烧录。EEPROM 兜底能保证不断网，但寻呼参数、天气设置这些
仍然只有文件系统正常才存得住。

### Wifi「重启后丢失」是怎么回事

这个现象有三个叠加的原因，都已修掉：

**① 文件系统没挂载，保存是静默失败的（主因）**

串口烧录整片镜像时如果不带文件系统镜像（脚本默认就不带），FS 区域是一片 `0xFF`，
LittleFS 必然挂载失败。原版代码里：

- `cfgLoad()` 挂不上就 `return`，配置全丢；
- `cfgSave()` 更坑 —— `open()` 失败后一路静默走完，**网页照样提示「已提交」**，
  实际一个字节都没写进去。于是每次重启都是出厂设置。

现在统一走 `fsBegin()`：挂不上就自动格式化一次再挂；`cfgSave()` 改成返回 `bool`，
写不进去当场通过串口报 `#WIFI+SAVEFAIL`、网页回 `-2`，页面直接红字提示
「配置没能写入 Flash，重启后 Wifi 会丢失」，而不是假装成功。

**② 后台连接状态机没有被驱动**

`staBegin()` / `staTick()` 这套非阻塞状态机写好后，`loop()` 里漏了 `staTick()`，
状态会永远停在「连接中」。现在已补上，并在 `loop()` 里同时跑 `staAutoTick()`。

**③ 掉线后从不重连**

`setup()` 里只连一次，失败就放弃；`wxTick()` 看到没连上也是直接 `return`。
路由器比模块晚开机、信号抖动、模块先上电，都会导致**永久掉线**，
天气推送自然也就没了。

现在会周期性重试：配过 Wifi 但没连上，且距离上次尝试超过间隔，就重新发起连接。
用户主动点断开则不再自动连回来（尊重用户选择）。

**重试不能太勤** —— 这是 ESP8266 的硬件特性决定的：STA 和 softAP **共用同一个射频**，
STA 每尝试连接一次就要切到目标路由器的信道，softAP 被迫跟着切，
连在 POCSAG 热点上的手机就会被踢下来。所以：

- 重试间隔按失败次数**退避**：30s → 60s → 120s → 240s → 上限 5 分钟；
- 连上后计数清零，下次掉线从 30s 重新开始；
- 凭据没变时用 `reconnect()` 而不是 `begin()` —— `WiFi.begin()` 会往 SDK 的 Flash 区
  写凭据（那片区域没有磨损均衡），反复调用既费 Flash，还可能撞上库的竞态把 WiFi 搞坏；
- 启动时 `WiFi.persistent(false)`：凭据我们自己存在 LittleFS，不让 SDK 反复擦写；
- 已是 `WIFI_AP_STA` 时不再调用 `WiFi.mode()`（切模式会重置 softAP）；
- 连接失败后**不**调用 `WiFi.disconnect()` —— 那会清掉 SDK 记住的 SSID，
  下次又得 `begin()` 重写一次；
- 自动重连的失败不上报串口，否则路由器不在时 STM32 屏幕每半分钟弹一次「WIFI FAILE」，
  让人误以为设备坏了。真连上时照常上报 `#WIFI+OK`。

顺带把 Wifi 页改成**轮询真实状态**：提交后每 1.2 秒查一次 `/wifistat`，
显示「正在连接…→ 已连接到「XX」，IP 192.168.x.x」或「连接失败：密码错误」，
不再只是干等一句「已提交」。状态区也新增了「已保存 Wifi」一行 ——
没保存会红字显示「未保存，重启后会丢失」，一眼能看出问题。

### Wifi 扫描的三个坑（都已处理）

**1. 必须用异步扫描。** `WiFi.scanNetworks()` 同步调用会阻塞 CPU 1~2 秒，
期间 Web 服务完全不响应，手机上的页面会「卡住」甚至请求超时。
这里用 `scanNetworks(true)` 异步扫描，由 `loop()` 里的 `scanTick()` 轮询结果，
扫描期间页面照常可用。另加了 20 秒超时保护，扫描卡死也不会一直占着状态。

**2. 畸形 SSID 会让整个 JSON 解析失败。** 路由器广播的 SSID 是原始字节流，
个别老路由用 GBK 而不是 UTF-8。这种非法序列塞进 JSON 后，浏览器端
`JSON.parse()` 会整体抛错 —— 结果就是一个坏名字让整个扫描列表显示不出来。
所以加了 `utf8Safe()`，把非法序列换成 U+FFFD（按 Unicode「最大合法子块」规则，
一段只换一个，不会吐出一串问号）。穷举 256 种单字节输入验证过，输出恒为合法 UTF-8。

**3. 热点名是别人可控的，不能用 innerHTML。** 谁都能把自家 SSID 设成
`<img src=x onerror=...>`。渲染结果一律走 `textContent` + `createElement`，
恶意名字只会原样显示成文字。已用最小 DOM 桩跑通真实渲染代码验证。

其余细节：结果按 RSSI 降序、只返回信号最强的 12 个（避免大 JSON 吃堆内存）、
JSON 分片输出、连接前先 `scanDelete()` 释放扫描结果占用的内存给 TLS 让路。

### 界面优化具体做了什么

- **深色模式**：CSS 变量 + `prefers-color-scheme` 跟随系统，右上角 ◐ 可手动切，选择存 localStorage
- **底部常驻操作栏**：手机上不用滚到底就能发送 / 清空，适配了 iPhone 底部安全区
- **顶部摘要条**：实时显示「已选 N 行 / 天气 N 行 / 预计 X 秒」，滚到哪都看得见
- **实时预估**：输入消息时即时算出字节数、单条耗时、整批耗时、切频次数（公式与固件一致）
- **行内校验**：频率 / 地址码填错立刻红框，提交时拦截并提示哪几行有问题
- **发送进度条**：显示 `第 n/N 条`，还带「本条还需 x.xs」的倒计时
- **隔行浅色底**：10 行不再糊成一片
- 四个页面配色、间距、圆角统一，Wifi 页和升级页也一起适配了深色

> 需要先装 [arduino-cli](https://arduino.github.io/arduino-cli/latest/installation/) 和
> `python -m pip install esptool`；`build_flash.py` 会自己把 esp8266 内核下载好。

## 三、Arduino 编译设置（关键）

1. 把 `ESP8266/` 整个目录复制出来，**文件夹名必须叫 `ESP8266`**（和 `.ino` 同名），
   用 Arduino IDE 打开 `ESP8266.ino`。
2. 开发板选 **Generic ESP8266 Module**，然后照下面设置：

| 选项 | 值 | 说明 |
|---|---|---|
| **Flash Size** | **8MB (FS:6MB OTA:~1019KB)** | 最关键的一项，选错会丢配置或刷完不启动；4MB 模块改用 `4MB (FS:2MB OTA:~1019KB)` |
| Flash Mode | DIO | 大部分模块都行；老模块启动不了就改 DOUT |
| Flash Frequency | 40MHz | |
| CPU Frequency | 80MHz | 160MHz 也行，但温度高、功耗大 |
| Crystal Frequency | 26MHz | 少数模块是 40MHz，看晶振上的字 |
| Upload Speed | 115200 | 稳定优先；串口线短可以上 921600 |
| Reset Method | nodemcu 或 ck | ESP-01S 通常用 ck |
| lwIP Variant | v2 Lower Memory | 省内存，给天气推送留余量 |
| **SSL Support** | **All SSL ciphers (most compatible)** | 天气接口走 HTTPS，必须开 |
| Debug port | Disabled | 串口要留给 STM32 |

> 全部用到的库都是 ESP8266 内核自带的，**不需要额外安装任何库**。
> 内核版本建议 2.7.4 或 3.0.2 以上（3.x 已验证 `FSInfo`、`HTTPClient` 接口可用）。

3. 点「验证」编译通过 → 「项目 → 导出已编译的二进制文件」，
   得到 `ESP8266.ino.bin`（内核 3.x 是**单个** bin，直接烧 0x0；
   内核 2.x 会导出两个文件，取名字里带 `0x00000` 之外的那个主 bin，或直接用 IDE 烧一次即可）。

## 四、编译 + 打包成单文件 Flash 镜像

### 方式 A：一键脚本（推荐）

```bash
python -m pip install esptool          # 只装这一次

python3 tools/build_flash.py                      # 自动装内核 → 编译 → 合并成 8MB 镜像
python3 tools/build_flash.py --layout 4m2m        # 想打成 4MB 布局就加 --layout
python3 tools/build_flash.py --with-fs            # 顺便把 data/ 预置配置打进文件系统
python3 tools/build_flash.py --port COM3          # 打包完直接烧录（Linux 用 /dev/ttyUSB0）
```

脚本会自动下载安装 `arduino-cli` 之外的一切（esp8266 内核等），
并把 **Flash Size 写成布局对应的值（默认 `8MB (FS:6MB OTA:~1019KB)`，即 `eesz=8M6M`）**，
保证编译参数和打包用的分区表严格一致 ——
这正是手动在 IDE 里最容易选错、也最难排查的地方。

产物在 `固件输出/POCSAG_ESP8266_8M6M.bin`。

### 方式 B：手动（IDE 编译 + 脚本打包）

1. 按第三节设置好板卡，点「验证」→「项目 → 导出已编译的二进制文件」，得到 `.bin`；
2. 打包：

```bash
python3 tools/pack_flash.py ESP8266.ino.bin
python3 tools/pack_flash.py ESP8266.ino.bin --fs littlefs.bin --out POCSAG_ESP8266_8M6M.bin
```

Windows 用户直接把 `.bin` 拖到 **`tools/pack_8m6m.bat`** 上即可。

### Flash 分区表（脚本已内置，三种布局）

| 布局 | Arduino 里的 Flash Size | 程序段 | LittleFS 起点 | LittleFS 大小 | RF 校准 | 系统参数 |
|---|---|---|---|---|---|---|
| **8m6m**（默认） | 8MB (FS:6MB OTA:~1019KB) | `0x000000` | `0x200000` | `0x5FA000` = 6MB | `0x7FC000` | `0x7FE000` |
| 8m7m | 8MB (FS:7MB) | `0x000000` | `0x100000` | `0x6FA000` ≈ 6.98MB | `0x7FC000` | `0x7FE000` |
| 4m2m | 4MB (FS:2MB OTA:~1019KB) | `0x000000` | `0x200000` | `0x1FA000` ≈ 1.98MB | `0x3FC000` | `0x3FE000` |

> 数值来源：esp8266 Arduino core 的链接脚本 `tools/sdk/ld/eagle.flash.8m6m.ld` 等，
> 其中 `_FS_start`/`_FS_end` 是映射地址，减 `0x40200000` 即 Flash 物理偏移。
> 三种布局的 OTA 程序空间都是 ~1019KB，区别只在文件系统大小和起点。

不传 `--layout` 时，脚本会读 `.bin` 头部记着的容量自动选：
按 8MB 编译 → 8m6m，按 4MB 编译 → 4m2m。容量和布局对不上会直接告警。

最后两段（RF 校准 / 系统参数）默认不写，是因为模块出厂时已烧好 RF 校准数据，
一旦被 0xFF 覆盖，发射功率和频偏都会劣化且很难恢复。
真需要写就显式传 `--rfcal esp_init_data_default.bin`，动手前建议先备份：

```bash
python -m esptool read_flash 0x7FC000 0x1000 rfcal_backup.bin      # 8MB 模块
python -m esptool read_flash 0x3FC000 0x1000 rfcal_backup.bin      # 4MB 模块
```

### 烧录

```bash
# 方式一：esptool，一个文件、一个地址
esptool --chip esp8266 --port COM3 write_flash 0x0 POCSAG_ESP8266_8M6M.bin

# 方式二：乐鑫 Flash 下载工具 / 安信可烧录工具
#   只加一行：POCSAG_ESP8266_8M6M.bin @ 0x0
#   SPI MODE / SPEED / FLASH SIZE 直接用打包结束时脚本打印的那组值
#   （8MB + DOUT + 40MHz 时是：DOUT / 40MHz / 64Mbit）
#   先点 ERASE 再点 START 更稳妥
```

> Flash 必须是**真实 8MB**（W25Q64）。如果模块原本是 1MB/4MB，得先换 Flash 芯片
> （或直接换 ESP-12F/ESP-12S 模块并确认上面焊的是 8MB），
> 否则按 8MB 设置会写入越界。网页「固件升级」页会显示 `ESP.getFlashChipRealSize()`
> 读到的真实容量，先去那看一眼再决定用哪个布局。

## 五、预置配置（可选，批量烧录用）

`data/pocsag.cfg` 是出厂默认配置（10 行全是 152.8250 MHz / 地址码 0000001~0000010 / 1200bps / 正相位，
第 1 行勾选了发送和天气）。两种烧进去的办法：

1. **Arduino 插件**：装 [ESP8266 LittleFS Data Upload](https://github.com/earlephilhower/arduino-esp8266littlefs-plugin)，
   选好 `Flash Size: 8MB(FS:6MB...)` 后点「ESP8266 LittleFS Data Upload」，会自动把 `data/` 传进文件系统。
2. **手动打包**：
   ```bash
   # mklittlefs 在 内核目录/tools/mklittlefs/ 下
   mklittlefs -c data -p 256 -b 8192 -s 0x1FA000 littlefs.bin
   python3 tools/pack_flash.py ESP8266.ino.bin --fs littlefs.bin
   ```

## 六、上位机使用流程

1. 模块上电后开一个名为 `POCSAG` 的热点（密码在 `ESP8266.ino` 顶部的 `AP_PSW` 改，留空即无密码）。
2. 手机连上后浏览器打开 **http://192.168.4.1**（或 http://esp8266.local）。
3. **群呼页** `/group_call`：
   - 10 行逐行填 频率 / 地址码 / 速率 / 相位；
   - 行首「发送」勾选 = 参与本次群呼，行尾「天气」勾选 = 接收天气推送，两者互不干扰；
   - 「全选发送 / 反选 / 全选天气 / 清空天气」一键操作；
   - 填好消息 → 「开始群呼」，按序号从小到大逐行发送（同频相邻行只切一次频）。
4. **天气推送**：选数据源 → 填 Key/位置/**城市名称** → 保存 → 「获取天气预览」确认内容 → 「立即推送天气」；
   打开「每日自动推送」并设定时刻后，设备每天到点自动推一次（需要先连上能上网的 Wifi 做 NTP 校时）。
   - Open-Meteo：免 Key，位置填 `纬度,经度`，例如 `22.8170,108.3665`（南宁）——服务器在境外，偶尔会超时。
   - 心知天气：位置填拼音城市名，如 `nanning`。
   - 和风天气：位置填 LocationID，如 `101300301`（南宁）。
   - **城市名称**：填了就会显示在天气开头，例如「南宁 多云 28℃ 湿度60% 东南风3级」。
     **三个数据源里只有心知天气会回传城市名**，Open-Meteo（默认源，免 Key）和和风都不返回 ——
     用这两个源时这里必须手动填，留空就不显示城市（页面会实时提醒）。
     固件默认值已填「南宁」，与默认位置 `22.8170,108.3665` 对应，改位置时记得一并改。
     **数字机不会显示城市名** —— 数字机只认 0-9 和 A-F。
5. **Wifi 页** `/wifi`：
   - **「扫描附近 Wifi」** —— 列出周围热点，按信号强度排序，显示信号格、信道、加密方式，
     当前连着的那个标「已连接」，点一下即可自动填入名称；
   - 填密码后点「连接 Wifi」，账号密码同时存进 ESP8266 和 STM32，重启自动重连；
   - 「在本机记住这个密码」可选，只存在你当前手机/电脑的浏览器 localStorage 里，不会上传到设备。
   - 扫描时模块会依次切信道，手机与设备热点的连接可能短暂中断几秒，属正常现象。
6. **固件升级页** `/webupdate`：以后 OTA 传 `.bin` 即可，不用再插串口。

## 七、串口协议（与 STM32 通讯，115200）

| 方向 | 命令 | 说明 |
|---|---|---|
| ESP→STM32 | `#SET+FREQ=152.8250` | 切频（同频时会自动跳过，省一次锁相） |
| ESP→STM32 | `#P00001230HT消息` | 发射：`#`+相位+7位地址码+响声+速率+类型+消息 |
| ESP→STM32 | `#WIFI+SAVESSID=xxx` / `#WIFI+SAVEPSK=xxx` | 让 STM32 存一份 Wifi 凭据 |
| ESP→STM32 | `#WIFI+OK` / `#WIFI+FAILE` / `#WIFI+SHOWIP=x.x.x.x` / `#WIFI+SHOWRSSI=n` | 联网状态上报 |
| STM32→ESP | `#WIFI+STA=ON` / `#WIFI+STA=OFF` | 开关 STA |
| STM32→ESP | `#WIFI+SET+SSID=` / `#WIFI+SET+PSK=` | 下发 Wifi 凭据 |
| STM32→ESP | `#WIFI+GETIP` / `#WIFI+GETRSSI` | 查询 IP / 信号 |

**可选补丁**：STM32 发完一条消息后回一句 `#TXOK`，ESP8266 收到就立刻发下一条，
不必等满「每行间隔」，10 路群呼能快很多。不改也能正常工作。

消息编码：网页声明 `charset=GB18030`，手机上输入的中文由浏览器直接编成 GB18030 字节透传；
天气文本是 UTF-8，由 `weather_gbk.h` 里的词表转成 GB18030 再下发给 STM32。

**词表覆盖 GB2312 全集**（6763 个汉字 + 约 800 个符号，约 52KB，存在 PROGMEM 不占 RAM）。
之所以要覆盖全集而不只是天气词汇：天气会带城市名称，城市名是任意给的字，
只收录几百个天气词的话，「南宁」「乌鲁木齐」会被整个丢掉，寻呼机上就是空的。
超出 GB2312 的生僻字（GBK 扩展区）会被丢弃 —— 这是有意为之，
与其显示一堆问号，不如什么都不显示。真遇到了换个常用写法即可。

## 八、常见问题

**网页打不开 / 连不上热点**
先看串口有没有打印，再看 `AP_SSID`/`AP_PSW`；ESP-01S 的 GPIO0 不能拉低（那是下载模式）。

**群呼只发了一行**
检查那几行的「发送」是否勾上，以及地址码是不是 7 位、频率是不是 `xxx.xxxx`（会自动补零，越界会被拒）。

**中文乱码**
确认浏览器没有强制用别的编码打开页面（页面已声明 GB18030）；汉字机本身也要支持 GB2312 字库。

**天气获取失败**
- 页面上方会显示路由器连接状态，没连上先去 Wifi 页配网；
- 时间没同步（NTP）时定时推送不会触发，连上外网后等几秒；
- Open-Meteo 在境外，超时就换心知/和风；
- `Flash Size` 没选带 SSL 的选项时会直接连不上 HTTPS。

**想改网页**
改 `原始html/` 里的 UTF-8 源文件，然后 `python3 tools/html2c.py` 重新生成 `ESP8266/html.c`。
生成器会把中文转成 GB18030 的八进制转义，保证任何编码的 IDE 编译出来都一样。

**发烧了**
发射前务必接天线或假负载，否则会烧毁 RF 功放；发射功率较大，请遵守当地无线电法规。
